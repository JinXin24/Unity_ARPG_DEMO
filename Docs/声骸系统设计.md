# 声骸系统设计文档

## 1. 概述

声骸（Echo）是一种**背包物品**，类型为 `ItemType.Echo`，可装备在角色身上。跟武器、消耗品一样走统一的物品管理，只是多了一套词条随机逻辑。

### 1.1 物品体系

```
Item（物品基类）
├── ItemId           → 查 ItemConfig 表
├── ItemType         → Echo / Weapon / Material / Consumable
├── Quantity          → 堆叠数（声骸不可堆叠）
└── InstanceData     → 子类特有的运行时数据
    ├── EchoInstanceData    → 主词条 + 副词条 + 等级
    ├── WeaponInstanceData  → 强化等级 + 精炼
    └── ...
```

| ItemType | 说明 | 装进背包装备？ |
|----------|------|:---:|
| Echo | 声骸，每个词条独一无二 | ✅ |
| Weapon | 武器 | ✅ |
| Material | 材料，可堆叠 | ❌ |
| Consumable | 消耗品，可堆叠 | ❌ |

> 声骸的特殊之处：不可堆叠（每个词条都不同）、可装备到角色、可强化。但这些只是 Echo 类型的行为覆盖，不改变"它是个物品"这一层。

### 1.2 声骸专属设定

**当前版本限定**：
- 等级上限固定 **25 级**，暂不考虑品质（金色/紫色等）
- 所有声骸一视同仁，无稀有度差异

| 概念 | 说明 |
|------|------|
| 声骸 | `ItemType.Echo` 的物品，可装备在角色身上 |
| 等级 | 固定 1~25 级，无品质区分 |
| 费用（Cost） | 声骸占用的负重，1费/2费/3费/4费 |
| 总费用上限 | 每个角色 **12 费**，5 个槽位 |
| 主词条 | 1 条，随声骸等级成长，类型由 Cost 决定 |
| 副词条 | 0~5 条，获取时随机 2~3 条，强化时解锁/升级 |
| 档位（Roll） | 副词条数值分 4 档，低档常见、高档稀有 |

## 3. Excel 配置表设计

### 3.0 `ItemBase` — 物品基表（所有物品共用）

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| ItemId | int | 物品唯一ID | 20001 |
| Name | string | 名称 | 幻形枭 |
| ItemType | string | 类型 | `Echo` / `Weapon` / `Material` / `Consumable` |
| Icon | string | 图标路径（Resources 之下） | `EchoIcons/Cost4/T_IconMonsterHead_34025_0_UI` |
| MaxStack | int | 最大堆叠数 | 1（声骸不可堆叠）/ 999（材料） |

> Echo 的 `ItemId` 映射到 `EchoConfig` 里的同 ID 行。运行时 `InventoryManager` 只认 `ItemInstance`，需要声骸特有逻辑时才向下转型。

### 3.1 `EchoBase` — 声骸扩展（仅 Echo 类型物品）

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| ItemId | int | 对应 ItemBase 的物品ID | 20001 |
| Cost | int | 费用 | 4 |
| MainStatPoolId | int | 主词条池ID | 401 |
| SubStatPoolId | int | 副词条池ID | 100 |
| InitialSubMin | int | 初始副词条最少几条 | 2 |
| InitialSubMax | int | 初始副词条最多几条 | 3 |
| MaxSubCount | int | 副词条上限 | 5 |

> **Cost 与池的关系**：4费声骸的主词条池有双暴（CritRate/CritDMG），1费池只有基础属性。不同 Cost 用不同 PoolId 来控制。

### 3.2 `MainStatPool` — 主词条池

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| PoolId | int | 池ID | 401 |
| StatType | string | 属性类型 | `CritRate` |
| Weight | int | 随机权重 | 80 |
| CurveId | int | 成长曲线ID | 3 |

> 主词条在**获取时**确定类型 → 查 StatCurve × 当前等级 = 最终数值。强化（升级）时数值自动按曲线重算。

**各 Cost 推荐池：**

| Cost | 可选主词条 |
|------|-----------|
| 4费 | ATK%, DEF%, HP%, CritRate%, CritDMG%, Healing% |
| 3费 | ATK%, DEF%, HP%, FireDMG%, IceDMG%, ThunderDMG%, WindDMG%, LightDMG%, DarkDMG% |
| 2费 | ATK%, DEF%, HP% |
| 1费 | ATK flat, DEF flat, HP flat |

### 3.3 `SubStatPool` — 副词条池

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| PoolId | int | 池ID | 100 |
| StatType | string | 属性类型 | `ATK%` |
| Weight | int | 出现权重 | 100 |
| RollMin1 | float | 档位1最小值 | 5.0 |
| RollMax1 | float | 档位1最大值 | 6.5 |
| RollWeight1 | int | 档位1权重 | 50 |
| RollMin2 | float | 档位2最小值 | 6.5 |
| RollMax2 | float | 档位2最大值 | 8.0 |
| RollWeight2 | int | 档位2权重 | 30 |
| RollMin3 | float | 档位3最小值 | 8.0 |
| RollMax3 | float | 档位3最大值 | 9.5 |
| RollWeight3 | int | 档位3权重 | 15 |
| RollMin4 | float | 档位4最小值 | 9.5 |
| RollMax4 | float | 档位4最大值 | 11.0 |
| RollWeight4 | int | 档位4权重 | 5 |

> **4 档 Roll 机制**：先按权重决定档位 → 再在 [min, max] 内均匀随机取值。权重 50:30:15:5 意味着大约一半出低档，5% 出顶档。

**副词条类型池（通用，所有声骸同一个池）：**

| 词条 | 说明 |
|------|------|
| ATK% | 攻击力百分比 |
| ATK | 攻击力固定值 |
| DEF% | 防御力百分比 |
| HP% | 生命值百分比 |
| HP | 生命值固定值 |
| CritRate% | 暴击率 |
| CritDMG% | 暴击伤害 |
| EnergyRegen% | 充能效率 |
| BasicATKBonus% | 普攻伤害加成 |
| SkillBonus% | 技能伤害加成 |
| HealingBonus% | 治疗效果加成 |

### 3.4 `StatCurve` — 数值成长曲线

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| CurveId | int | 曲线ID | 3 |
| Level | int | 等级 | 1~25 |
| AtkPercent | float | 该等级 ATK% 主词条数值 | 6.0 |
| CritRate | float | 该等级暴击率 主词条数值 | 5.0 |
| CritDmg | float | 该等级暴伤 主词条数值 | 10.0 |
| ... | float | 每种主词条类型一列 | ... |

> 每个 CurveId 对应一条等级→数值的曲线。不同主词条类型共用同一个 CurveId 的不同列。这样一张表管所有成长曲线，不用每个 Pool 建一张。

### 3.5 `EchoDebug` — 调试表（仅开发用）

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| DebugId | int | 调试模板ID | 1 |
| Name | string | 标签 | "满暴4费" |
| Cost | int | 费用 | 4 |
| MainStat | string | 固定主词条 | `CritRate` |
| MainValue | float | 固定主值 | 99 |
| SubStat1 | string | 副词条1 | `ATK%` |
| SubValue1 | float | 副值1 | 500 |
| SubRoll1 | int | 副档位1 | 4 |
| ... | ... | SubStat2~5, SubValue2~5, SubRoll2~5 | ... |

> 一行一个测试模板。`ConfigManager.DebugMode = true` 时，获取声骸走这个表不走随机池。

### 4.1 枚举定义

public enum StatType
{

    ATKPercent,    // 攻击力%
    DEF,           // 防御力(固定)
    DEFPercent,    // 防御力%
    HP,            // 生命值(固定)
    HPPercent,     // 生命值%
    CritRate,      // 暴击率%
    CritDMG,       // 暴击伤害%
    FireDMG,       // 火伤%
    IceDMG,        // 冰伤%
    ThunderDMG,    // 雷伤%
    WindDMG,       // 风伤%
    LightDMG,      // 光伤%
    DarkDMG,       // 暗伤%
    EnergyRegen,   // 充能效率%
    BasicATKBonus, // 普攻加成%
    SkillBonus,    // 技能加成%
    HealingBonus,  // 治疗加成%

// 费用
public enum EchoCost { One = 1, Two = 2, Three = 3, Four = 4 }

### 4.2 运行时数据结构

```csharp
// ===== 物品基类 =====
public enum ItemType { Echo, Weapon, Material, Consumable }

public class ItemInstance
{
    public int itemId;          // 对应 ItemBaseSO
    public ItemType itemType;
    public int quantity;        // 堆叠数（声骸固定为 1）

    public ItemBaseSO Config => ConfigManager.Instance.GetItemBase(itemId);

    // 声骸升级：EchoInstance → 声骸特有字段
    public EchoInstance AsEcho() => itemType == ItemType.Echo ? (EchoInstance)this : null;
}

// ===== 声骸扩展 =====
[System.Serializable]
public class EchoSubStat
{
    public StatType type;
    public float value;
    public int rollQuality;   // 1~4
}

[System.Serializable]
public class EchoMainStat
{
    public StatType type;
    public float value;       // 查 StatCurve[level] 得到
}

public class EchoInstance : ItemInstance
{
    public int level;                   // 1~25
    public EchoMainStat mainStat;
    public List<EchoSubStat> subStats;  // 0~5 条

    // 从扩展配置推导
    public EchoItemSO EchoConfig => ConfigManager.Instance.GetEchoItem(itemId);
    public int Cost => EchoConfig.cost;

    public EchoInstance()
    {
        itemType = ItemType.Echo;
        quantity = 1;  // 声骸不可堆叠
    }
}
```

### 4.3 InventoryManager — 统一背包（挂场景单例）

```csharp
public class InventoryManager : Singleton<InventoryManager>
{
    [SerializeField] private List<ItemInstance> items = new();  // Inspector 直接看

    // ===== 通用物品操作 =====
    public void AddItem(ItemInstance item);
    public void RemoveItem(ItemInstance item);
    public List<ItemInstance> GetByType(ItemType type);
    public ItemInstance Find(int itemId);

    // ===== 声骸业务 =====
    // 随机获取（同时加入背包）
    public EchoInstance AcquireEcho(int itemId);
    // 流程：查 ItemBase → EchoBase → 加权随机主词条 → 随机 N 条副词条(去重)
    //       → 算主词条数值(Curve × lv1) → AddItem → 返回

    // 强化
    public void EnhanceEcho(EchoInstance echo, int levels);
    // 流程：level += levels → 重算 mainStat = Curve[新level]
    //       → +5/+10/+15/+20/+25：未满5条新增 / 已满随机升级一条

    // ===== 装备 =====
    public void EquipEcho(int characterId, EchoInstance echo, int slotIndex);
    public void UnequipEcho(int characterId, int slotIndex);

    // ===== 查询 =====
    public List<EchoInstance> GetAllEchoes()
        => GetByType(ItemType.Echo).Select(i => i.AsEcho()).Where(e => e != null).ToList();
    public float GetTotalStat(int characterId, StatType type);

    // ===== 调试 =====
    public bool debugMode;  // true = 走 EchoDebug 表，不走随机

    #if UNITY_EDITOR
    [SerializeField] private int debugAddItemId;
    [ContextMenu("添加物品")]
    void EditorAddItem() { }
    [ContextMenu("清空背包")]
    void EditorClear() { items.Clear(); }
    #endif
}
```

> 武器也是同理——后续加武器时给 `InventoryManager` 加 `AcquireWeapon`/`EnhanceWeapon` 方法，不另起单例。

### 4.4 随机算法

```
获取声骸：
  ┌─ MainStatPool[poolId] ──────────────────┐
  │ 1. 筛选该池所有行                         │
  │ 2. 按 Weight 加权随机 → 选中一种 StatType │
  │ 3. 查 StatCurve[curveId][level] → value  │
  └──────────────────────────────────────────┘

  ┌─ SubStatPool[poolId] ───────────────────┐
  │ 1. 随机 N = [initialMin, initialMax]     │
  │    （鸣潮初始 2~3 条）                    │
  │ 2. 循环 N 次：                            │
  │    a. 按 Weight 加权选 StatType           │
  │    b. 去重：已选类型不再出现               │
  │    c. 按 RollWeight1~4 决定档位           │
  │    d. 在 RollMin~RollMax 间均匀随机 value │
  │ 3. 返回 List<SubStat>                    │
  └──────────────────────────────────────────┘

强化触发（+5/+10/+15/+20/+25 各一次）：
  ┌─ 未满 5 条 ── 新增一条（同上流程，去重）   │
  └─ 已满 5 条 ── 随机选一条已有 →             │
                   档位+1（最多4档）            │
                   数值在新区间内重Roll         │
```

## 5. 与战斗系统对接

### 5.1 属性汇总

```
CharacterState
  └─ CharacterStats（新增）
       ├─ baseStats: 角色基础属性（等级/职业）
       ├─ weaponStats: 武器属性
       └─ echoStats: InventoryManager.Instance.GetTotalStat(charId, statType)
```

在 `CharacterState.Update()` 中不做属性查询（性能浪费）。只在以下时机汇总：
- 声骸装备/卸下时
- 声骸强化后
- 角色升级时

汇总后写到一个 `currentStats` 字典，战斗结算直接读。

### 5.2 伤害计算

```csharp
// DamageCalculator.cs
public static int CalcDamage(DamageInfo raw, CharacterStats stats, CharacterStats targetStats)
{
    float atk = stats.Get(StatType.ATK) * (1 + stats.Get(StatType.ATKPercent) / 100f);
    float critRate = Mathf.Min(stats.Get(StatType.CritRate), 100f);
    float critDmg = stats.Get(StatType.CritDMG);
    
    bool isCrit = Random.Range(0f, 100f) < critRate;
    float dmg = raw.Damage * (atk / 100f);
    if (isCrit) dmg *= (1 + critDmg / 100f);
    
    return Mathf.RoundToInt(dmg);
}
```

## 7. 背包与装备

### 7.1 物品→背包→装备 数据流

```
ItemConfig + EchoConfig（Excel）
       ↓
  ItemInstance ← InventoryManager.AddItem()
       ↓
  EchoInstance ← ItemInstance.AsEcho()（声骸专属操作）
       ↓
  CharacterEchoSlots.EquipToSlot() ← 校验 12 费上限
       ↓
  CharacterStats 汇总属性
```

### 7.2 角色装备槽

```csharp
// 5槽位，总费用上限 12
public class CharacterEchoSlots
{
    public const int SlotCount = 5;
    public const int MaxTotalCost = 12;

    public EchoInstance[] slots = new EchoInstance[SlotCount];

    public int UsedCost => slots.Where(e => e != null).Sum(e => e.Cost);
    public int RemainingCost => MaxTotalCost - UsedCost;

    public bool CanEquip(EchoInstance echo) => RemainingCost >= echo.Cost;

    public bool EquipToSlot(int slotIndex, EchoInstance echo)
    {
        if (slotIndex < 0 || slotIndex >= SlotCount) return false;
        if (echo != null && !CanEquip(echo)) return false;
        slots[slotIndex] = echo;
        CharacterStats.MarkDirty(); // 通知属性重算
        return true;
    }
}
```

### 7.3 声骸获取流程

```
1. 怪物死亡 → 掉落声骸（概率由怪物配置决定）
2. InventoryManager.AcquireEcho(itemId)
3. 查 ItemBase → 查 EchoBase
4. 随机主词条 + 副词条 → 生成 EchoInstance
5. InventoryManager.AddItem(echoInstance)
    └─ 背包满 → 提示/自动分解
```

### 7.2 声骸获取流程

```
1. 怪物死亡 → 掉落声骸（概率由怪物配置决定）
2. InventoryManager.AcquireEcho(itemId)
3. 查 ItemBase → EchoBase → 随机主词条 + 副词条
4. 生成 EchoInstance → AddItem 加入背包
5. 如果背包满 → 提示/自动分解
```

## 9. 关键设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 主词条是否可改 | ❌ 不可改 | 获取时确定后锁死，刷声骸的核心驱动力 |
| 副词条强化策略 | 满5条后随机升级已有 | 鸣潮式，防止无限叠新词条 |
| 强化等级节点 | +5/+10/+15/+20/+25 | 5 次副词条操作机会 |
| 主词条数值随等级 | 查曲线表，不随机 | 稳定性 > 随机感，主词条管"确定性" |
| 调试模式实现 | Excel 独立表 + bool 开关 | 零代码侵入随机逻辑 |
